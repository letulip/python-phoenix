# Python Phoenix – working rules for Claude

## Non-negotiables
- Never push to `main`. One branch per wave (`feat/wave-N`), full cycle in that branch: work → gate → owner playtest →
  fixes → PR → the owner merges. The owner creates the GitHub repository and `main`.
- Before every commit run `npm run check` (content gate, service-worker precache list, harness mismatch check, node tests). It must print `gate: OK`.
- `content/tasks.json` and `docs/CURRICULUM.md` are generated by `tools/build_content.py`; never edit them by hand.
- Keep `sw.js` SHELL in sync with the files on disk (`tools/check_sw.py` enforces it) and bump `VERSION` in `sw.js`
  together with `APP_VERSION` in `app.js` and `package.json` on every release.

## Engine facts that bite
- The Pyodide worker is an ES module worker that loads `pyodide.mjs` through `import()`. Do not switch back to a
  classic worker with `importScripts`: the Claude desktop browser pane blocks cross-origin classic scripts in workers,
  and that pane is the only place the stand is tested before the owner's playtest.
- Pyodide version is pinned in two places: `src/runner/worker.js` (CDN URL) and `sw.js` (`PYODIDE_CACHE`).
- Timeouts are enforced by the main thread (`src/runner/client.js`): it terminates the worker and promotes a pre-warmed
  spare. `runner.py` must stay pure standard library because the content gate runs it in local CPython 3.14.
- CodeMirror ships as one vendored bundle (`vendor/codemirror.js`). Never load CodeMirror modules from a CDN at runtime.

## Content rules
- Statements, code, identifiers and talk tracks are English; hints and explanations exist in both English and Russian.
- Every exercise carries a one-line `story_en`; every module carries chapter title, intro story and closing line in both
  languages. The storyline is "Operation Phoenix": Pixel the cat's studio Purrfect Code, Captain Byte, Grandma Ada,
  Timmy (12), Coach Topspin, Dr. Candle, the Over the Hill garage. Keep it funny and readable by a twelve-year-old;
  the owner's son may use the stand later.
- Worlds: shorts, bybit, tennis, oth, everyday, game, neutral. No QA-themed stories (the owner declined that world);
  SDET skills live inside the other worlds.
- Hidden tests must be deterministic and use `check(actual, expected, label)` with a readable label; structural checks go
  through `ast_tools`. Exercises about an idiom should assert the idiom is used (`uses_name`, `count_calls`, ...).
- Keep stories short: module story ≤ 90 words, exercise flavour line ≤ 60 words (the gate enforces both).
- Every task/refactor exercise carries `LEVELS`: a middle and a senior solution, each with a short reasoning in both
  languages (`middle.code` may be omitted and then equals `SOLUTION`). The gate runs both codes against the hidden
  tests and the examples; drills carry no levels. The senior note says what the code does not decide, not only what it does.
